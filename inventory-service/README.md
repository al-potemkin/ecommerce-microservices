stock_movement

Это журнал всех изменений остатка: приход, корректировка, резерв, списание, возврат резерва. Таблица stock_item хранит только текущее число, а журнал объясняет, откуда оно взялось.

Аудит: кто, когда и почему изменил остаток (например, «−3, инвентаризация»). Без этого расхождения не разобрать.
Идемпотентность: Kafka и повторы HTTP могут доставить одну операцию дважды. Уникальный ключ в журнале (например, orderId + sku + тип) не даёт применить её повторно.
Сверка: on_hand можно пересчитать из журнала и найти ошибку.
