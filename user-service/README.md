# user-service

Профиль покупателя и его адреса доставки. Аутентификация и роли находятся в Keycloak, корзина живёт на фронтенде, заказы и их история в order-service.

## Стек
Java 21, Spring Boot 4, PostgreSQL 16, Flyway, MapStruct, Lombok. Порт: 8085.

## Ответственность
- Профиль пользователя: создаётся лениво при первом `GET /api/users/me` из claims токена (`given_name`, `family_name`, `email`). После создания профиль независим от Keycloak, все поля необязательные.
- Адреса доставки: несколько на пользователя, один из них по умолчанию.
- Менеджеры и покупатели работают с профилем одинаково, ролей для эндпоинтов не требуется.

## API (через api-gateway, префикс `/api/users`)
Все эндпоинты требуют `Authorization: Bearer <JWT>`. Пользователь определяется по `sub`, поэтому чужие данные недоступны (чужой `id` адреса даёт 404).

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/users/me` | Профиль (создаётся при первом обращении) |
| PUT | `/api/users/me` | Полная замена полей профиля, `null` очищает поле |
| GET | `/api/users/me/addresses` | Список адресов, адрес по умолчанию первым |
| POST | `/api/users/me/addresses` | Новый адрес (первый становится адресом по умолчанию) |
| PUT | `/api/users/me/addresses/{id}` | Замена полей адреса |
| PUT | `/api/users/me/addresses/{id}/default` | Сделать адресом по умолчанию |
| DELETE | `/api/users/me/addresses/{id}` | Удалить адрес (если он был по умолчанию, им становится самый старый из оставшихся) |

Телефон в формате E.164 (`+380501234567`). Ошибки возвращаются в формате ApiProblem (RFC 9457).

## Правила сохранения адреса из заказа (реализует фронтенд)
- Если у профиля нет адресов, после успешного заказа адрес из формы сохраняется в профиль.
- Если адреса есть, данные из формы заказа профиль не перезаписывают.
- Заказ хранит снимок данных доставки, а не ссылку на адрес.

## Конфигурация
| Переменная | Назначение |
|---|---|
| `SERVER_PORT` | Порт сервиса (8085) |
| `USER_DB_HOST`, `USER_DB_PORT`, `USER_DB_NAME`, `USER_DB_USER`, `USER_DB_PASSWORD` | PostgreSQL |
| `JWT_ISSUER_URI` | Issuer Keycloak (`http://localhost:8180/realms/ecommerce`) |
| `JWT_JWK_SET_URI` | JWKS Keycloak внутри docker-сети |

## Запуск
```
docker compose up -d --build user-db user-service
```
Healthcheck: `GET /actuator/health/readiness`.

## База данных
Схема управляется миграциями Flyway (`src/main/resources/db/migration`), Hibernate работает с `ddl-auto: validate`. Таблицы: `user_profile`, `user_address` (не более одного адреса по умолчанию на профиль гарантирует частичный уникальный индекс).
